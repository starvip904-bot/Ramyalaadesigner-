# DOKKAN — Patch 01 (تفعيل المتجر وتوجيه تسجيل الدخول)

## الملفات
استخرج محتويات هذا الملف المضغوط فوق مجلد المشروع الرئيسي `Ramyalaadesigner--main` مع السماح باستبدال الملفات الأربعة الموجودة:

- `app/actions/onboarding.ts`
- `app/onboarding/store/page.tsx`
- `app/page.tsx`
- `app/[...slug]/page.tsx`

## ماذا يصلح هذا التحديث؟
- يستبدل Server Action المعطل `REDA_STORE_CREATION_DISABLED`.
- يستخدم RPC الموجودة فعلًا في قاعدة البيانات `dokkan_bootstrap_owner` لتفعيل عضوية المالك للمتجر الأساسي الموجود.
- يوجّه المستخدم المسجل الذي لا يملك عضوية نشطة إلى شاشة التفعيل بدل أن يفشل عند فتح لوحة التحكم.
- بعد نجاح التفعيل ينتقل المستخدم إلى `/dashboard`.

## مهم
قاعدة البيانات الحالية تحتوي بالفعل على متجر DOKKAN أساسي وفرع رئيسي وإعدادات متجر. لذلك هذا التحديث لا ينشئ متجرًا ثانيًا؛ بل يفعّل حساب المالك للمتجر المجهز. لم يتم إجراء أي تعديل على قاعدة البيانات.

## نتائج الاختبار
- نجحت اختبارات `lib/pos.test.ts` و`lib/workflows.test.ts` و`lib/reda-scope.test.ts`.
- لم يكتمل فحص TypeScript أو `next build` لأن تثبيت الاعتماديات تعطل/انتهت مهلته، وأصبحت بعض الحزم غير متاحة محليًا. أعد تشغيل `npm ci` في بيئتك ثم `npm run lint` و`npm run build`.

## ما لم يُنفّذ بعد
هذه حزمة إصلاح الدخول والتفعيل فقط، وليست اكتمالًا لكل وحدات InvenPOS. ما زالت نقطة البيع في `components/pos-page.tsx` تعتمد على بيانات mock، ولا توجد حاليًا دالة `dokkan_post_sale` في قاعدة البيانات المتصلة. كما أن بعض صفحات المبيعات والمرتجعات والتحويلات والتقارير والموظفين ما زالت غير مكتملة أو تعرض واجهات عامة. يجب استكمال عقود قاعدة البيانات والعمليات المالية قبل تفعيلها حتى لا يحدث خصم مخزون مزدوج أو تسجيل عمليات غير مكتملة.
